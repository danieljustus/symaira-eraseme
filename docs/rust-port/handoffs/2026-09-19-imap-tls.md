# Rust cut 2026-09-19 — IMAP TLS (implicit TLS + STARTTLS)

Slice: DOM-006 transport, second part. Branch `migration/rust-imap-tls-20260919`,
based on `b8d88e65` (PR #981, plain-TCP transport).

## Why this slice comes before `poll_inbox`

`AllowInsecureCleartextAuth` is set by **no** product path: `internal/email/types.go`
documents it as an escape hatch for controlled environments, no environment
variable feeds it and no handler argument sets it. The plain-TCP transport
ported in #981 is therefore unreachable in production — every real mailbox is
reached over implicit TLS or STARTTLS. Wiring `poll_inbox` on a plain-only
transport would have produced a tool that always refuses. TLS first, wiring
second.

## What is ported

- `ImapDialer` keeps Go's precedence: an injected root store wins, otherwise the
  bundled `webpki-roots` store is used. Go's `imapTLSConfig` sets
  `MinVersion: tls.VersionTLS12` and `ServerName` = configured host; rustls'
  safe default protocol versions are exactly "TLS 1.2 or newer", so the minimum
  version semantics match. The crypto provider is named explicitly
  (`rustls::crypto::ring`) instead of relying on process-level auto-detection,
  which would make feature unification load-bearing.
- Implicit TLS handshakes before the greeting is read; rustls completes the
  handshake lazily on the first read, exactly where Go's session object starts
  working.
- STARTTLS follows Go: only when the server advertises `STARTTLS` in
  `CAPABILITY`; `<tag> STARTTLS` then its tagged OK, then the handshake. The
  transport is swapped in place, because the reader was created before the
  handshake and cannot be rebuilt (rustls sessions are not cloneable).
  Documented assumption: the server sends nothing between its tagged OK and our
  ClientHello (the client speaks first).
- No `InsecureSkipVerify` equivalent exists; no product path sets it in Go
  either.

## Evidence

`rust-tests/parity/oracle/imap-transport/transcript_cases.json` now marks **all
eleven** cases byte-replayable, including the two TLS ones. The fixture records
the command transcript and the results, never certificate material: each side
mints its own localhost certificate per run — Go through the package's test
helper, Rust through `rcgen` as a **dev-dependency**. `cargo deny check` stays
green (advisories, bans, licenses, sources), and no private key enters the
repository.

Both TLS transcripts match Go byte-exactly:

```
starttls_login      <tag> CAPABILITY, <tag> STARTTLS, <tag> LOGIN "testuser" "testpass", <tag> EXAMINE INBOX, …
implicit_tls_login  <tag> CAPABILITY, <tag> LOGIN "testuser" "testpass", <tag> EXAMINE INBOX, <tag> LOGOUT
```

The suite asserts that both TLS cases really ran (`server_mode != "plain"`,
count >= 2) so a silently skipped case cannot look like covered behaviour.

## Known divergences

- **Root store**: Go uses the platform store, the port the bundled webpki roots.
  A private or enterprise CA installed in the OS store is trusted by Go and not
  by the port.
- **Cleartext refusal**: unchanged from #981; with TLS ported it is now the
  correct behaviour rather than a limitation.
- **Reader buffering during the upgrade**: the reader is a `BufReader`, so the
  STARTTLS upgrade assumes nothing arrived after the tagged OK. Bounded by the
  protocol (the client speaks first after STARTTLS).
- Non-ASCII folder names remain UTF-8 instead of Go's modified UTF-7
  (`ponytail:` marker in `client.rs`).
